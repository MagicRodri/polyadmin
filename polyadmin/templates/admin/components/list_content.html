{# The interactive region of a list page: toolbar + table + footer. Rendered both inside the full page (resource/list.html) and directly as an HTMX fragment (Renderer.render_list_fragment) -- same markup either way, so search/filter/sort/pagination never disagree between a fresh load and a partial swap. Laid out after shadcn/ui's Tasks example: one full-width column, no side panel. The toolbar is a single row -- search and the faceted filter dropdowns left, the page's own actions right -- then the table, then DataTablePagination. The filters that used to live in a Django-admin-style right-hand panel are now those faceted dropdowns (components/filters.html), which is what frees the full width for the table. Button placement follows the example: everything that *narrows* the table is on the left, everything that *acts on* it is on the right, so the two never interleave as filters come and go. Bulk actions are the one addition -- they appear in the left cluster only once rows are selected, since that's a verb about the current selection rather than a page-level action. Mirrors go-polyadmin's list.html. #} {% from "admin/components/icons.html" import icon %} {% from "admin/components/ui/dropdown-menu.html" import dropdown_menu %}
