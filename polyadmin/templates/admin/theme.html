{# Design tokens + frontend runtime. Mirrors go-polyadmin/templates/admin/theme.html. This is the "take the tokens, leave the React" half of plan/shadcnui-usage.md: the CSS variables below are shadcn/ui's stock Zinc theme, and every class string in polyadmin/ui.py resolves to them (bg-background, text-muted-foreground, border-input, ...) rather than to a literal Tailwind palette. Restyling the whole admin -- or flipping it to dark -- is therefore a change to these variables and nothing else. Script order in here is load-order-critical, top to bottom: 1. the dark-class script must run *synchronously before paint*, otherwise a dark-mode reload flashes the light palette for a frame (this is the same reason next-themes injects an inline script); 2. the Tailwind CDN script must load *before* `tailwind.config` is assigned -- backwards from what you'd guess. The CDN script is what defines the global `tailwind` object in the first place; setting `tailwind.config = {...}` before it exists throws a silent `ReferenceError` (swallowed by the browser, no visible failure) and Tailwind falls back to its stock palette. Every custom color -- `bg-background`, `text-foreground`, the `chart-*` tokens -- then resolves to nothing, which is exactly what happened here: confirmed with a real headless-Chrome run where `tailwind.config` came out as `{}` and not one token-based utility (`.bg-background`, `.text-chart-1`, ...) existed in the generated stylesheet. This is also Tailwind's own documented order (https://tailwindcss.com/docs/installation/play-cdn#customizing-tailwind); 3. Alpine *plugins* must load before Alpine core, per Alpine's docs -- core initializes on load and only sees directives registered by then. `x-trap` (action_confirm_modal.html) and `x-collapse`/`x-anchor` (the ui/ components) come from these three plugins. Everything is CDN-loaded: there is no frontend build step in either language implementation. #} {# (3) Alpine plugins, then Alpine core, then HTMX. SortableJS (defer, so it's guaranteed ready before any x-init that calls Sortable.create -- see ui/table.html's reorderable drag handle) is the framework's one non-Alpine dependency: drag-and-drop has no small CSS-only equivalent the way every other component here gets by with Alpine alone.
